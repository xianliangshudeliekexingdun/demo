# 06 项目管理方式调整

> 档案状态：历史决策与阶段证据。文中“当前／未实施”按记载时点阅读；现行规则见[主题索引](../../游戏设计/README.md)，最新状态见[功能模块](../../功能模块.md)。

决策日期：2026-10-16。状态：按用户要求整理文档、移除项目内旧管理集成。

## 背景

用户认为OpenSpec不适合，要求去除，整理为项目架构、功能模块和按大任务分文件的历史决策。旧规格、任务、验证、操作和讨论材料分散，部分讨论稿仍把已实现法术写成草案，动作试作完成数也容易被当成品质通过。

## 决定与实施

- docs/项目架构.md集中工程分层、职责、参数、坐标、工具与验证。
- docs/功能模块.md集中现行行为、升级/预设/流程、状态、待办和试玩记录。
- docs/历史决策按六个大任务分档，同任务内按日期追加，保留被取消方案、理由和认可边界。
- README负责导航，AGENTS维护协作约定；不另生成第二套项目进度清单。
- 移除本项目openspec目录、六个.agents/skills/openspec-*目录、skills生成标记.openspec-target和tools/openspec.ps1；旧架构、迁移、规则、火球/构筑操作和构筑讨论Markdown合并后移出活动目录。

移除范围是本项目集成。个人全局工具、Godot MCP、其他专业技能和原引擎不作为本次卸载对象。

## 状态迁移

保留外观、自动接续、六火球升级、五法术基础/冷却的具体认可；阶段B待试玩。角色动作与3D按暂停/取消，不因试作或旧勾选恢复任务。历史数值和验证按日期记录，不作为2026-10-16新玩法验收。

运行表仍是唯一参数来源，文档中的值只解释当前快照或历史理由；管理调整不需要改场景、玩法、UI、数值或资产。

## 恢复与核对

合并前把53个旧管理文件、README和AGENTS存为一次性恢复ZIP：build/project-management/2026-10-16/before-document-reorganization.zip，不作为活动规划读取。

批量删除命令被自动审批拒绝，仅返回blocked by policy，未给更细原因，删除未执行。改用可恢复的路径校验归档，15个旧管理目标移入build/project-management/2026-10-16/retired；项目根目录的规格、skills和调用脚本均不再启用。

整理后检查本地链接、入口和残留引用，对135个代码、场景、参数、测试、资产、工具、引擎和支持JSON文件作前后SHA256核对。结果在build/project-management/2026-10-16/verification.json。

核对通过：50处本地链接有效，135个受保护文件没有变化，15个旧管理目标全部移出活动目录，恢复ZIP完整；现行管理文档没有旧流程入口。

本轮没有玩法或画面改动，不启动游戏、重新导出或将历史验证重计为体验验收。

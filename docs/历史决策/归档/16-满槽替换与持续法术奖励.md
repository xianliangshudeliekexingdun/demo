## 用户确认

冰系交付检查期间，用户指出满槽后不能终止三选一，应允许继续替换已有法术，先对齐规则。说明原实现“满槽只出已有升级，八术满级后跳过法术奖励”后，用户明确确认新法术从一级开始，并认可继续三选一、选新术后指定旧槽、取消返回原三卡且不重抽。

随后补充确认：八术满级、本次三张都是新法术时，允许保留构筑、放弃本次奖励并开门，避免奖励强迫拆解成型组合。同样的满槽全新候选即使库存尚未全满级也提供此出口；混有可升级卡时可直接升级。不增加免费重抽或指定法术必出。

## 当前行为

| 情况 | 处理 |
|---|---|
| 未满八槽、选择新术 | 直接学习一级新术 |
| 选择已学且未满级法术 | 升级原槽，不进入替换页 |
| 满槽、选择新术 | 保留本次三卡，进入待替换子页 |
| 替换子页 | 先选旧槽，再确认；确认前不删除旧术、不领取、不开放门 |
| 确认替换 | 仅指定槽变成新术一级，使用正常新学初始状态，不继承旧等级／冷却 |
| 取消或Esc返回 | 回到原三张卡，库存与RNG不变 |
| 满槽且三卡全新 | 可放弃本次奖励保留构筑，消耗本房奖励并开门 |
| 八术全部三级 | 满级术不占候选，继续提供未持有法术；不因槽满跳书 |

保留宝物及其他七术等级／剩余冷却，不改变原职业宝物触发定义；学派数量、被动、共鸣及奖励资格根据实际持有法术即时重算。原战斗临时对象已在清场清理。替换页仍属reward阶段，只走路线计时，人物／战斗／冷却冻结；暂停／失焦连路线计时也停。

core负责pending、请求ID、房间revision、原八槽核对与本房消费守卫。验证完成后才原子写入；暂停、错误槽、旧请求、跨房与重复提交不能扣掉旧术或二次领取。UI创建控件时捕获原token，不能借新页身份提交；Main兼容原String请求，新UI使用Dictionary，并拒绝非整数槽位／token／revision。

# 前四十五房商店接入

> 档案状态：历史决策与阶段证据。文中“当前／未实施”按记载时点阅读；现行规则见[主题索引](../../游戏设计/README.md)，最新状态见[功能模块](../../功能模块.md)。

日期：2026-10-19。用户要求“接下来完善关卡流程，前45关，我们先加入商店房间”。本任务将商店接入实际路线；沿用此前已确认的[节点／补给](../../游戏设计/历史方案/03-首关流程与场景.md#12-已确认的精英与商店节点)与[商店经济](../../游戏设计/历史方案/07-金币商店与品质.md)，按当前火冰内容和实际遭遇接线，不扩为正式Boss、后15房、局外收益或最终平衡验收。

## 路线与交互

第9、24、33、42战斗房领奖后走门进入独立无敌人商店，再从商店上方门进入下一战斗房。商店不占战斗房号，原45战斗房、466只敌群、36次法术与9次箱奖励保持。顶部三个节点从core真实序列预览本节点及后续节点，商店独立标记“店”；45房末端继续保留最后三战斗房。

商店采用庭院石工、独立柜台、原有字体／图标及原创程序几何。中央通路可直接走门；靠近左侧柜台才领取本店一次免费成长／回血并打开商品。直接通过会放弃本店补给和购物。柜台关闭后需先走出互动范围再靠近，避免关闭立即重开；重新打开不刷新、补货、重复补给或重置购买额度。

柜台首次接触先加生命上限，再按新上限回复；上限增加不另加当前生命。已有生命契约沿用基础上限池倍率规则；同店买到生命上限宝物不追补免费恢复。补给和交易均由core结算，UI、柜台动画和模型不拥有规则。

## 金币与商品

使用现行24通用＋16火＋16冰活跃宝物池，按实际持有法术／等级和已持有宝物过滤；归档灵契不入店。箱与店共用既有阶段品质，首店蓝色保证及合法缺池回退，至多三个不同候选；不足则少展，空池仍可补给并离开。最多购买一件，购买立即生效，不占八法术槽；没有指定职业／通用配额、额外法术奖励、回售、刷新或付费回血。

补齐原经济源已有的精英清房加奖，以当前encounter.kind判定，不按房号或混编中出现一只精英认定为精英房。15／30／45仍是强化精英，只走精英收入，不冒充正式Boss奖金／回血。开局、基础清房、精英加奖、价格、品质、保证及补给幅度继续读取原data，商店新增data只拥有空间与接触参数。

真实Route逐房清场的无消费账本，到四店前累计收入分别为66／218／330／442，45战斗房总收入486。它们是当前遭遇派生的验证快照，不是新的参数源；不能照搬旧21件／完整60房经济模型里的首领收入、14件上限或概率统计。当前最多9箱＋4次购买；实际持有随合法候选与玩家选择变化。

购买请求只携带商品ID与创建UI时的房间revision，价格取core固定库存。core核对阶段、暂停、存活、余额、资格、商品和本店额度后提交；余额不足、过期／跨房、重复或伪造请求不扣款、不改变宝物和RNG。金币取得、消费、剩余分别记录，商店和结算均不接局外账本；独立首房真实结算保持。

## 计时、表现和验证边界

商店行走和购物均计入路线总时间，不进入combat_time；购物冻结人物、法术冷却与敌人，暂停／失焦停止全部计时。商店换场、关闭／恢复界面沿用松键门。已有莉奈跑动只跟随真实位移，未新增角色动作或位图资源。

实现遵循[Godot焦点导航](https://docs.godotengine.org/en/stable/tutorials/ui/gui_navigation.html)和[Dictionary拷贝边界](https://docs.godotengine.org/en/stable/classes/class_dictionary.html)；以原4.7.2 exe本机解析和真实渲染检查为准。

商店专项、主suite、火冰回归、文字矩阵、真实Main和来源审计分别记录于[本轮QA](../../../build/qa/route-shops-20261019)，现行有效结论集中在[功能模块](../../功能模块.md#5-当前有效验证证据)。受控库存／钱包／属性夹具不作自然获得或玩家难度证据，真实自然路线另记。验证仅本地，自动检查退出；未导出、提交、上传或自动启动交付互动游戏。用户试玩与最终美术／平衡认可待后续反馈。

本轮复用的旧45房视觉脚本在预检中仍按归档F04／旧十火候选与旧按钮文字寻找操作，分别在第9／18／28房中止。已将测试选择策略同步到正式20术、满槽放弃及具名替换按钮；这些预检日志单独保留为visual-preflight／second／third-preflight，不作商店规则失败或交付通过证据。未为适配测试修改法术、敌人、关卡或宝物数值。

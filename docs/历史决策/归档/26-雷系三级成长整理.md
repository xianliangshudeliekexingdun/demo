# 雷系三级成长整理

日期：2026-10-21。本轮是实施前设计整理与离线核算；尚未接入雷系运行，不产生实机、像素、自然路线、性能或最终平衡验收。

> 前三节保留先整理阶段；用户后续授权、雷云循环修复与十术实装结果见第4—6节。后续原生规则通过仍不产生实机／像素或最终平衡验收。

## 1. 用户要求与范围

用户在讨论下一步方向后要求：“可以，先推进雷系，把十个法术的三级成长整理出来”。用户同时提出，火冰雷三系抽取方案是否等所有法术系列制作完成后再调整更好。

本轮采用先完成各系法术、后统调抽取的顺序：待火／冰／雷／风／岩／灵契六系法术制作完成后，再统一讨论、核算与调整多系抽取概率、触媒倾向和价格；不先制作三系阶段调优，不据此批准总纲12中候选公式／参数。制作期间现行抽样方式保持，仍核合法入池、升级、去重、满槽替换等流程，流程缺陷不因延期而放置不修。

用户授权的是先推进并整理雷系十术三级；本轮产出的新增机制归属与具体数值标为提案，不能把本次整理写成十术已实施或逐项获批，也不自动重启游戏。实机、截图、自然整局和性能继续按用户安排留待后续统一测试；本轮不导出、提交、推送或上传。

## 2. 提案形成

系统主题新增[雷系法术成长](../../游戏设计/雷系法术成长.md)，沿用原15稿十个ID／名称、三个起手、唯一被动、八槽三级与雷系连接身份。原[15稿](../../游戏设计/未来方案/15-正式雷系法术与职业宝物.md)及[候选JSON](../../../tools/balance/five_schools/lightning.json)保持原字节，不在编号稿追加最新状态；现行主题与功能模块链接本版提案。

一级保留原职责与数值锚，二级加强基础能力，三级强化本术机制。适配10项旧来源：LB01／LB02／LB03／LB04／LB06／LB09／LB10、LP02、LG02／LG03；保留LB05／LB07／LB08、LP01／LP03、LG01为未来专属道具设计来源。没有独立专属升级，也不要求恢复原16件配额或将全部旧装备效果压入三级。

L05自然三级易伤收拢到云团自身，不再要求另持L08；L07自然三级成熟导电邻弧不再要求另持L04，但保留旧导电年龄、主目标存活、2邻敌和不递归边界。L08三级只提高自然过载的真实强化边，不增加总节点或向单体返还空边。L10只延长以后新施加／刷新导电，连接增距不扩大各术首射程和独立布点范围。

数值整理有意保持原一级和各级主伤锚；未采用增加额外尾弧、再叠裁决条件附伤或提高被动／回盾来追平火冰的做法。是否需要进一步强化，留实际接入后的同口径核算及后续统一试玩判断。

## 3. 核算与验证边界

使用game-balance-analysis梳理参数、情境关系和可执行边界。新增[lightning_growth离线工具](../../../tools/balance/lightning_growth/README.md)，参数明确标为版本化设计提案；原five_schools候选与冻结来源不改写，工具不参与游戏加载。

核算以原稿三级作对照，区分单体与多敌总量、无旧导电与已有网络、自然与追加、普通与60%CDR。L05唯一云的后施替换必须取消旧未发生波；L07邻弧只有旧导电年龄合格、主目标完成伤害后仍存活才出现。固定持续缺盾只作回复上界，不视为真实生存或GT01无限蓄能。

只读设计复审发现L05保留旧替换／1.4秒共享门时有冷却阈值风险：50%CDR下新云首落距旧云第三落1.6秒，55%下仅1.2秒而被门挡，增加CDR可能反降本术输出。新稿明确门挡仍占目标名额、无临时补选、不消耗首次有效落雷／易伤机会，并要求工具补45%／50%／55%／60%扫描。此问题显式保留为实施前待收口，不以提高系数补模型／时序缺陷。

最终[离线结果](../../../build/qa/lightning-growth-design-20261021/results.json)为6689项检查／0失败，含5760条独立法术预算、120条本体±10%敏感性和16条研习／共鸣／高暴击边界，另列回复／网络案例。场景与检查不能重复累计为玩法测试数；[人读报告](../../../build/qa/lightning-growth-design-20261021/report.md)保留L05冷却阈值警告。50%→55%CDR的三级静止单敌60秒期望DPS约92.35→68.47，并非“高CDR已通过最终平衡”。

模型复核修正了两项工具问题后再复跑：逐边在下一边实际到达时重新读取终点导电／遮挡资格，避免用上一击的终点状态兑现已失效增距；L09初始缺盾与最大缺口分开，满盾后有声明损失供给时可以合法施放，回复仍不超过初始缺口＋真实供给。另核主击击杀后不刷新死主目标导电。这些是模型忠实度修复，不改提案系数。

静态保护与引用核对见[整理审计](../../../build/qa/lightning-growth-docs-20261021/results.json)。模型没有真实AI、完整八槽构筑、宝石核心联动、自然选卡、局长或性能；文档／数值通过不扩为跨系最终平衡或用户试玩认可。

## 4. 后续授权：先修雷云，再实装十术

同日用户进一步明确：“可以，先解决雷云高冷却缩减反而降低输出的问题，再按这套方案实装雷系十个法术”，并要求对齐“抽取方案”的含义。此授权覆盖雷云循环修复和十术正式接入，不等于提前统调抽取、增加雷触媒价格或开展实机。

抽取方案在本任务中指清房法术书三选一的合法候选、学派倾向、新学／已有术升级机会，以及触媒权重与费用；不包含宝物箱品质或宝石抽取。当前仍先过滤满级等非法候选，再对同一合法法术ID池逐张加权、不放回抽样；没有另设新术／升级分组比例。装备火／冰触媒按原乘数提高关联法术ID权重，雷术按基础权重进入池，暂不增加雷触媒。六系完成后再统一讨论与调整。

## 5. 雷云修复取舍

初稿的唯一云替换会丢未发生波，跨云1.4秒伤害门又会挡下一云首落。曾检查“单云连续时钟、重施刷新”的更小变更，自然单独可通过，但穿插追加会改变相位，部分有限观察窗仍反降，故未采用。

正式规则改为每次成功施法独立拥有有限3／3／4次落雷与原寿命、位置、等级、伤害倍率和自然首次逐敌易伤集合；后施不取消旧波，不覆盖旧context。移除跨cast共享伤害门，改为每cast每波每敌一次；原各波本身仍间隔1.4秒。追加云按自身倍率独立结算且无自然易伤资格，不能重入施法或生成新云链。基础伤害系数未上调，恢复此前被截断的伤害是明确的生命周期修复收益。

[运行源派生工具](../../../tools/balance/lightning_growth/cloud_fix.py)直接读取新正式data，不维护第二套默认值；[13187项／0失败、3294条预算](../../../build/qa/lightning-cloud-fix-20261021/results.json)覆盖三等级、30／60／300秒、0—60%CDR逐百分点、单体／密集、自然／追加及固定弱追加混合。自然单独与追加单独无反降，混合各档不低于同档自然单独，原始波次／本体系数不减。三级60秒50%／55%／60%CDR期望DPS约119.00／134.48／150.37，原初稿约92.35／68.47／74.93。

短易伤窗口随冷却移动，对另一来源固定到达时点的覆盖有36处小波动，最大约0.24%；[报告](../../../build/qa/lightning-cloud-fix-20261021/report.md)与机器结果如实保留，不宣称任意多来源条件总量必然单调。旧proposal_v1、旧模型和原冻结结果保留原阶段含义。

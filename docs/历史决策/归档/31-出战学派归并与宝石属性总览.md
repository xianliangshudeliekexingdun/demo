# 31 出战学派归并与宝石属性总览

日期：2026-10-25。现行规则见[局外养成](../../游戏设计/局外养成.md)，当前实现与证据见[功能模块](../../功能模块.md)。

## 用户要求

用户提出两项出战界面修改：一是把“本局学派”与“法术触媒”合并，触媒装备哪一系，开局三选一就用该系的系列；没有装备触媒时全系列三选一。二是 UI 需要大改，并要求结合专业 UI 设计技能讨论；无论最终版式如何，都必须展示玩家装备好宝石后的属性效果。

## 确认的取舍

- 未装备触媒时，从六系各三张、共 18 张基础术中随机抽三张；允许同学派重复，不抽非起手术。用户明确选择此项，而不是“三系各一张”或“60 术全池”。
- 属性展示采用八项完整口径：攻击、生命上限、护盾上限、防御、暴击率、暴击伤害、冷却缩减、战斗移速；每项按“基础 → 宝石加成 → 最终值”呈现，并标注上限。
- 属性总览出现在出战准备页与战斗 HUD／暂停页；本轮未改宝石工坊内既有的紧凑文字，工坊仍承担背包、抽取与精粹培养。

## 规则实现

core 在 `configure` 时从出发快照的 `equipment.catalyst` 与 `levels` 推导本局学派，触媒优先于旧的 `route_school` 字段；账号快照未装备触媒时进入全系列，`opening_school = all`。全系列抽取使用独立随机流（`seed ^ 0x2545F4914F6CDD1D`），不消耗奖励采样流，因此同一 seed 下奖励序列与装备触媒时一致；抽取结果在开局前固定并缓存，快照与多次读取稳定。没有 `equipment` 字段的旧测试／独立首房入口保留火系默认，`route_school` 仍可作为显式覆盖供旧 fixture 使用；未知学派继续报错。

快照新增 `opening_school`、`opening_source`，`route_school` 保留兼容。`meta` 在出发快照中新增 `stat_breakdown`，把“基础／净宝石加成／最终／上限”一次算好；战斗层只读透传，不在表现层重算战斗数值。

## 界面实现

出战准备页移除六颗学派按钮：顶部显示“本局学派 · 火系／全系列”及来源（触媒名称、等级、本系书奖优先强度；未装备时说明 18 张随机三张）。中段左侧为四槽宝石逐颗明细（品质、名称、三条属性、核心效果、同名不生效红字），右侧为八项属性瓦片，底部为生效核心列表。全部槽位可点击进入宝石工坊。

新增只读组件 `scripts/ui/loadout_summary.gd`，统一属性瓦片与核心标签的画法；出战页用两列四行，暂停页用四列两行，战斗 HUD 用两行摘要，三者共用同一份出发属性。暂停页原来的密排属性段落被替换为总览面板。开局三选一标题补充“本局学派 · 某系（触媒）／全系列（未装备触媒）”。显示不改变生命、伤害、冷却、拾取或随机资格。

## 验证范围

规则专项（60 房含新增开局规则用例）2529 项、宝石经济专项 2123 项均 0 失败；无头冒烟确认准备页、开局预览、战斗 HUD 与暂停页可构建，出发快照含八项 breakdown。未做实机、截图、像素可读性、自然整局与性能测量；字体裁切、瓦片密度与小尺寸可读性留待统一实机检查。本轮不导出、不远端构建、不提交。

# 34 战斗画面第一轮渲染与表现改造

更新：2026-10-26。本档只记录本轮画面改造的方向、授权与实施／验证范围；现行实现状态见[功能模块](../../功能模块.md)，规则仍以[六个系统主题](../../游戏设计/README.md)与data为准。

## 1. 用户确认与方向

2026-10-25 用户提出：接下来任务是优化游戏内战斗表现画面，包括 UI 布局、战斗场景、渲染风格、法术特效、角色模型，并明确“先做最明显的，如渲染这类”。据此本轮按下列顺序实施：

1. 渲染基线；
2. 法术与战斗反馈；
3. 战斗 HUD 层级；
4. 战斗场景模板；
5. 角色／敌人表现。

已决定方向：**月光遗迹 × 暖金魔导**。环境保持低饱和冷灰蓝石材，角色与关键物件偏暖，敌方危险继续用独立珊瑚红／玫红体系，UI 沿用深蓝／暖金／青色。该方向优先利用现有批准资源，不需要新增外部模型或字体。

## 2. 已实施

### 渲染基线

- 战斗环境改为 Filmic 色调映射与轻微远景雾；雾只用于压低外围遗迹，不覆盖战斗区、脚下和危险范围。
- 主光改为暖色并保留唯一投影方向光，补光为较弱的冷色方向光；相机、战斗几何、MSAA 与视口尺寸不变。
- 全局 Glow 仍关闭；此前 Compatibility 下的 A/B 已否决全局泛光，继续用局部光斑与真实灯光维持暗背景。
- 石材／泥土／布料／金属材质分层：石材保持高粗糙并降低镜面，金属包边与王冠加入金属度，进口金／黄铜等物件不再等同于粗糙石墙。

### 法术与战斗反馈

- 敌弹在覆盖层中增加深色分离底衬，火焰、金色包边和明亮命中都不应盖住敌方弹体。
- 友方持续区域特效、燃烧、吟唱火光降低亮度；命中类效果保留高亮并新增短促命中核心，形成“持续低、瞬发高”的层级。
- 玩家受伤环按真实字段区分：消耗生命用暖红，仅消耗护盾用青色；不改变伤害、护盾或事件。

### 战斗 HUD

- 生命条加厚、字号提高，护盾保持次级信息；低生命只改变 HUD 强调色，不代表新状态或新规则。
- 法术槽名称按被动／吟唱／冷却／就绪着色；宝物条在八个法术槽上方居中；路线模式在房间标题下方补回“剩余敌人”，Boss 血条占用该行时让位。
- 低频的出发属性摘要改为随“操作与流程提示”显示，减少常驻干扰；完整属性仍可在暂停页查看。

### 场景与模型表现

- 六类庭院模板保留几何差异，同时增加克制的色板差异：石材偏冷，trim 在暖金、青铜、绿调之间区分，且房号 10 后略作变化。
- 莉奈保留已批准模型与待机／跑动／分段施法动作，只调整材质响应；没有新增动作、没有整图晃动替代步行动画。
- 敌人与 Boss 程序材质区分金属／布料／石材，预警与受击覆盖透明度略微增强；不新增外部资源，不改变轮廓碰撞与索敌。

## 3. 规则与边界

本轮全部为表现层改动：不修改 core 规则、data 数值、生命／护盾、伤害、范围、寿命、预警时间、随机奖励或领取资格；不改相机视距与战斗几何；不新增或替换正式美术资源；不导出新版。

## 9. 2026-10-26 首版用户静帧反馈与原因分析

用户提供战斗截取图并询问“感觉效果不太好这是什么原因”。[原始用户反馈图](../../游戏设计/参考图/20261026-战斗特效/05-magic-missile-v01-feedback.png)按附件原字节保存，来源文件为 `codex-clipboard-227939b4-f885-42e6-ba81-8afd6c4d411d.png`，SHA-256 为 `422dd56669233656798311290777490b04816a461b1f769fd834c867bbc810d4`。该图是用户提供的首版静帧证据，处于设计目录隔离范围，不是制作参考图或游戏运行素材，也不是代理新启动／自动截取的画面。

可见问题：画面中的小型粉紫弹头更接近带表面高光的实心珠子，魔法能量与尾迹的整体形态不明显；石砖、友方法术线和攻击预览同时占据画面，弱外光难以建立层次。本反馈表明首版观感需要返修，不将其扩大成全部规则、动作或性能的否定。

代码可确认的原因：弹头以轴比约1.2的近对称椭圆为主体，内部接近不透明，使用球面法线明暗和小面积近白高光，容易产生宝石／塑料珠的材质观感。内部细线在小弹头的有限像素中不易形成清晰的大尺度能量流。尾迹历史仅0.14秒，且同时受5.2倍判定半径／1.05米长度上限、几何收细和 Shader 透明度衰减约束；例如教学弹速3.2米／秒仅对应约0.45米历史路程，实际可辨认的尾部还会更短。局部散光的峰值透明度仅0.14，且先于近不透明弹头绘制，最亮区域大多被主体覆盖，真正露在外侧的散光已衰减到很低强度；与复杂地面叠加时更难看清。原版小尺寸、低透明外光的处理过于保守，结构齐全仍未建立目标能量质感。

尚未确定：静帧不能判定拖尾是否始终未绘制，亦不能评价完整流动节奏、出生增长过程、命中消散和帧时；若另有绘制缺失，仍需动态或分层检查。当前运行的原 Godot 进程启动晚于本版飞弹源文件更新，未发现必须归因为未重启旧进程的证据；本次未关闭、重启或控制它。

建议后续返修优先调整能量主体的前后轮廓与透明结构、减少依赖微小高光／细纹，在实际镜头中建立清晰的连续尾迹，再调局部光与细节；保留现有判定与终止事实来源，仍按 v0.1 验收。该建议尚未在本次实施。本轮仅分析、保存用户图和更新文档，没有改运行代码／data，没有进行游戏启动、截图或玩法测试。

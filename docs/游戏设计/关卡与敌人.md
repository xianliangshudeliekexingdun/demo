# 关卡与敌人

本文归并现行60房路线、敌群、四Boss及敌方压力规则。当前参数以加载的data为准；[设计21](历史方案/21-非Boss四阶段与弹幕碰撞方案.md)、[22](历史方案/22-四个Boss与必金双奖励方案.md)、[24](历史方案/24-四阶段伤害成长与快慢弹幕.md)保留各轮获准方案和计算快照，不重复维护完整数值表。

## 路线、空间与奖励

路线分为1—15前期、16—30中期、31—45后期、46—60超高难度，各段末房为Boss。56个非Boss房共929只，四段分别104／195／266／364只；另四个Boss本体，最终Boss整战最多再召四只。固定遭遇933只与一次实际击杀数须区分，随从是否生成、是否被击杀由战斗决定。

| 房间 | 当前Boss | 检验重点 |
|---|---|---|
| 15 | 岩冠守卫 BOSS01 | 冲撞、扇射与恢复期反打 |
| 30 | 千瓣花母 BOSS04 | 扇射、缺口环与落印换位 |
| 45 | 符阵监守 BOSS02 | 交替扫射、落印与符线分区 |
| 60 | 遗迹之心 BOSS03 | 三阶段综合与有限召援 |

当前有52个法术书节点、12个宝物箱节点；9／24／33／42／54房后进入五间独立商店，不占战斗房号，也不增加战斗清房或魔尘。金币、补给与购买规则见[商店经济](商店经济.md)。

四Boss清场固定出现书和必金箱，包含60房。先完成法术书，再依据选择后的构筑生成并缓存纯金候选；两项权益完成才开门，末房同样领奖后走门结束。金色合法池为空时由本关独立庭印兜底，不降为紫色；庭印不进普通池／商店，也不立即补血盾。不叠旧规划中的额外Boss金币、魔尘或回血，保留当前节点收入与清房补盾。

场地使用首房加六模板和跟随镜头，出生集中北侧并保留掩体／可走范围。旧12×14米、三Boss、50普通房／285只均为历史规划，不覆盖当前data。顶部三节点表示真实房间类型与当前／后续房间，末端保留最后三房；不是一房内“战斗／奖励／传送”阶段。

## 敌群与分批节奏

M01追击扑击、M02快速点射、M03预警冲锋、M04锁点落印，配合M05慢扇、M06缺口慢环、M07快速扫射与EL01／EL02精英混编。前三房保留教学；慢扇第5房、缺口环第18房、落印第25房、快扫第32房引入，先认识单类威胁，再增加交叉火力。每段保留补给后回落及Boss前缓冲，不把全段都做成同一强度。

整批出怪需同时满足总人数与远程、环、扫、重型角色限额；上批剩余不超过指定人数才尝试后批，不能把整房总数当并发数量。北侧15个候选出生位先完整预警，激活时重查墙柱、敌人和玩家安全距离；不安全继续等待，不强塞到玩家身边。波间不清弹、补盾或重置法术CD。

## 房间伤害与快慢弹幕

主动攻击按“原怪物／变体基值 → 最终弹型单颗基值 → 本房damage倍率一次”计算，再交玩家防御、护盾与生命事务。身体接触使用小型／重型／精英基值乘独立body_damage一次，不能在旧四段最终数组上继续倍乘。伤害与生命成长分别配置，不能把生命倍率误当攻击倍率。

普通／非Boss精英各有独立档位，当前四阶段逐步提高受击代价；前三房保留教学。Boss读取本关专用damage倍率，逐招基础与身体各乘一次，不叠普通怪倍率。怪物出生保留房间规格，已离体弹不因切换页面或显示刷新重算伤害；最终召援明确取59房普通规格，也不再乘Boss倍率。

快速点射和扫射负责短反应窗口，慢扇和慢环负责持续封路。同一次多扇保持中线；双环共用缺口，下一次完整攻击才旋转缺口；双扫第二扫反向并另有预警。点射后续每颗重新锁向并提前提示，离体后不追踪。慢环名义方位始终删去连续三个，表内方位数与实际发弹数不能混用。

“单轮弹数”“同次子轮数”“整次总弹数”和“起手周期”分开定义。周期至少容纳所有子轮、逐发过程与恢复，不能首轮未完就重启。整次攻击先预约全部子轮容量再起预警；不足只等待重试，不删旧弹、不截断缺口。快弹源与大组弹幕分别错峰起手，快弹保留最小起手距离；这些是起手约束，允许已离体弹交错。

非Boss四段敌弹＋待发预算归非Boss规则，Boss房有本体专用预算，召援与本体共享，不能借59房更大预算绕过本关上限。弹丸撞墙／掩体消失、达到寿命或射程结束，不反弹。冻结暂停本体预警和待发；死亡／推开取消待发，已发弹独立继续。多源间隙可读性和高弹量性能尚待实机，静态容量通过不保证任意位置都可躲。

## 接触、Boss阶段与构筑窗口

身体以相对扫掠圆判定，共享0.8秒接触间隔和原0.6秒受击保护；同刻多身体只取最高合法一次。主动攻击／飞行弹先结算；活动扑击／冲锋、冻结、死亡、出生预览与出生保护期间关闭对应身体伤害。不新增实体堵路或强制击退，近身构筑仍可利用预警和恢复期。玩家防御与先盾后血见[战斗与成长](战斗与成长.md)。

Boss主招式串行，阶段按实际剩余生命推进，致死优先，可爆发越阶段。转换清敌方旧弹／地面危险并有缓和，玩家仍可输出、移动和推进冷却；不锁血、回血或重置玩家状态。四Boss显式抗推、硬冻系数为零，保留减速、寒霜／碎冰窗口和相关核心作用，不能把抗硬冻写成免疫全部冰系机制。

最终Boss最多两组M01＋M02，同时最多一组；前组存活时保留后组机会，恢复窗口再尝试，不无限补怪。召援独立安全出生并完整预警，不补盾或重置冷却；击败本体立即清除剩余召援及危险，进入双奖励，无需追加收尾战。

## 敌方魔法飞弹表现验收标准（v0.1）

2026-10-26 用户明确首件样板为魔法飞弹，确认以下验收标准后授权“可以，请你制作”。对象沿此前讨论的敌方普通飞弹；标准确认与最终样板的视觉验收分别记录。四张参考图与授权沿革见[历史34](../历史决策/归档/34-战斗画面第一轮渲染与表现改造.md)。

当前能量版 v2 采用前端聚集、后部拉伸的半透明主体，以近白亮核、玫红／紫红宽能量带、前景弧形流光与连续发光尾迹构成主次；取消首版的球面高光。具体轮廓和配色待实际画面评审后再修订。火焰、燃烧烟雾、炭黑和余烬不属于本件魔法飞弹的材质目标。

| 项目 | 首版通过条件 | 需要返修的表现 |
|---|---|---|
| 主体造型 | 实际镜头下能辨认完整、集中的弹头及前后方向；静帧可见亮核、带色主体和较暗边缘的层次 | 均匀实心圆点、完整静态图标或失去轮廓的白色光团 |
| 能量质感 | 正常速度播放能看到主体内部或表面的能量变化，仍保持外形稳定；变化跟随飞行方向组织 | 只有整颗图片平移／旋转，或靠高频闪烁和整团缩放表现能量 |
| 拖尾 | 从弹头后方连续接出，向末端逐渐收细并淡出；方向与实际路径一致；结束时自然收尾 | 与弹头脱节、像等宽棍子、可见重复贴片断口、忽然整条删除或长时间残留 |
| 光与细节 | 主体始终比外光更易识别，光屑服务于方向和运动感；小尺寸优先保证主体与尾迹 | 多层亮光叠成白斑，或小粒子／复杂纹样抢过弹头，亮背景上主体消失 |
| 命中与消散 | 真实接触对应一次短促的魔法冲击，先集中释放，再散成光屑／衰减光迹；尾迹有结束过程 | 火焰爆炸、与普通小弹不相称的大爆炸、重复冲击，或寿命／射程结束和清场也伪装成命中 |
| 实战辨识 | 在 1280×720、现有相机与庭院背景下保持可见；交叉飞行时可追踪各弹头，亮地砖及友方法术附近仍能辨认危险来源 | 只在暗背景近景好看；实战依赖放大才看清；尾迹形成实心墙或掩盖缺口与预警 |
| 危险范围 | 紧实主体与真实判定尺度相称；衰减外光、尾迹和消散明显属于装饰，不制造新的危险范围暗示 | 光晕被误认成更大的碰撞体，或主体位置与真实飞弹／接触点不符 |
| 时序与稳定性 | 释放、飞行、接触、消散前后连贯；暂停冻结，房间切换清理；减少动态仍保留主体、方向和危险识别 | 为展示而改弹速／寿命，暂停仍流动，近屏边突然裁切、闪层或旧房残留 |

未来视觉评审材料：同一版本的单发完整动画（正常速度；慢放只辅助检查）、实际镜头与庭院中的多发／交叉飞行对照，以及对应的飞行中／命中／消散静帧。先评单件观感，再评实战可读性，任一项目需要返修均不能称视觉通过；代码解析或结构测试单独记录。当前实机、截图、自然整局和性能暂缓约定不变；首版静帧反馈指出主体偏实体珠子、能量与拖尾辨识弱，现已完成能量版 v2 返修；用户随后提供 v2 近景／战斗全景并明确“很好完美”，认可本次魔法飞弹展示／试玩观感，保留现版。该认可不扩大为所有法术、完整60房、高弹量性能或逐项像素专项；首版图不作为新版证据。认可范围与后续讨论见[历史34第11节](../历史决策/归档/34-战斗画面第一轮渲染与表现改造.md#11-2026-10-26-魔法飞弹-v2-观感认可与后续战斗视觉讨论)。本次原因分析见[历史34第9节](../历史决策/归档/34-战斗画面第一轮渲染与表现改造.md#9-2026-10-26-首版用户静帧反馈与原因分析)。

表现入口为[魔法飞弹渲染器](../../scripts/presentation/route_magic_missile_vfx.gd)和三份原生 Shader，唯一视觉配置为[magic_missile_vfx.json](../../data/magic_missile_vfx.json)。连续尾迹保存世界坐标路径，绘制时与弹头一起投影；无逐弹节点、独立墙钟或游戏 RNG。四个绘制节点使用三份共享材质；绘制顺序为路径尾迹、聚集主体、前景弧光、真实碰撞冲击，弧光不会被主体覆盖。飞弹层位于战斗预警／血条／标签之上、HUD 之下；未新增图片、字体、全局 Glow 或角色动作。[独立预览场景](../../tests/previews/magic_missile_preview.tscn)提供单发、四向交叉、64 发、暂停及减少动态，只作后续评审入口，不进玩家菜单或导出白名单，当前未交互启动。

工程集成另核：不改变 core 的位置、碰撞、伤害、弹速、寿命、射程、发弹数量与游戏随机流；表现使用快照时钟。当前最高非Boss阶段容量为 320（来自运行 data），后续容量／性能检查应覆盖真实上限，不能用删弹或缩小真实缺口换取效果。具体设备帧时预算需在性能测试获安排后按同机同场景基线确定；此处不宣称性能通过。

命中来源：`route_enemy_combat._update_projectiles` 保留原碰撞／伤害分支，另记录独立的逐弹终止日志；路线快照通过 `enemy_projectile_ends` 提供序号、飞弹 ID、玩家接触／撞墙／自然结束原因、亚步时间、弹心终点、接触表面点和法线。日志仅有限保留并深拷贝，不进入玩法 effects／event_seq，不消费 RNG 或二次调用伤害。渲染器去重后只为真实玩家／墙体接触生成冲击；到期、超程或无记录消失仅收尾，非战斗／新房立即清理。

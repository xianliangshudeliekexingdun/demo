# 正式火系候选数值工具

本工具保存[正式火系方案](../../../docs/游戏设计/历史方案/13-正式火系法术与职业宝物.md)实施前的独立数值模型。用户现已通过方案并授权实装；新原生规则与真实画面证据见[实装QA](../../../build/qa/formal-fire-implementation-20261018)，本目录模型结果不替代实机测试。关系按情境比较，不以十个法术DPS相等为目标。

以下“当前代码／旧core／未来候选”均指审查阶段。`build/qa/formal-fire-20261018`保留当时输入哈希与完整结果；本次实现已修改这些运行源，重新运行本工具会读取新data，不能声称重现旧输入。需要对照时先核对报告的source hash，不覆盖旧报告。正式运行默认值只在data。

## 两层证据

| 层次 | 工具／结果 | 可以回答什么 |
|---|---|---|
| 当前真实代码 | `runtime_baseline.gd`、`baseline.py`；[当前基线](../../../build/qa/formal-fire-20261018/baseline.md) | 使用实际Route／Spell／Artifact core，核九保留法术三级、施放时序和旧G03触发；受控锚点，不是完整战斗 |
| 未来抽象候选 | `model.py`、`parameters.json`、`run.py`；[报告](../../../build/qa/formal-fire-20261018/report.md) | 假想位置下的有限时间输出、共享燃烧库存、触发贡献、职业／通用组合与边界；没有接入游戏 |

当前代码直接加载`data/balance_candidates/first_run_v1.json`，该文件的旧candidate状态字符串不代表未加载。F04当前仍在游戏中；工具仅从正式火方案中排除它，不执行迁移。

## 输入与单位

`parameters.json`保留来源路径与候选差异，不另建一份运行默认值。九保留ID的三级原始系数、CD、吟唱、范围与持续时间来自现源；仅覆盖F03首落固定且100%、F05显示名，并新增F11。职业B03／G03有明确重做，新增B11／P06／G04。修正就绪／次弹／附加锁点三项模型缺陷后，依据身份敏感性选定每跳25%与G04额外倍率＋2；模型修复与数值调参分开留痕。具体值可以改JSON后另存结果。

| 参数组 | 单位／口径 |
|---|---|
| 攻击／伤害 | HP；系数为攻击倍数，不是整数百分数 |
| CD／吟唱／区域／状态 | 秒；CD释放后开始，各槽并行；总CDR最高60%、CD最低0.2秒 |
| 场景位置／范围 | 米；合成目标半径明确为0.3米，并非当前M01真实半径0.45米 |
| 燃烧 | 1份／敌，0.25攻击每0.5秒；4秒8跳共200%，P06为6秒12跳共300%；不暴击 |
| 引爆 | 未来完整跳数×每跳系数×当下增幅×F07倍率；消费后清空，不重复兑已跳伤害 |
| 法阵覆盖 | 固定0或1的近似输入；保留自身区域排除与三级保留时间，不声称统一全局快照 |
| 随机性 | 固定8个seed；暴击与落点随机，输出均值／中位／最小／最大／SD／均值标准误；不是真人群体分布 |

“无额外CDR”组仍会在三火时拥有真实的10个百分点共鸣CDR。`high_cdr`是总CDR60%的压力覆写，不声称当前装备可自然达到。P05减剩余CD作为独立事件处理，不加进面板CDR。

## 场景与固定库存

每个比较分别计算30／60秒：单体静止、六目标密集、六目标疏散传播、六目标合成正弦移动。疏散场景的邻距为3～3.47米，超过F01小爆炸，用于看F11的覆盖价值。移动场景含6目标，不能因为其总伤害高于1目标就声称更易命中；应与同为6目标的密集组比较。

常规目标无限生命、不死亡、不转火；没有敌方AI、移动决策、击退改变轨迹、墙或过量伤害。火弹按落点时刻采样近似，光束／落点／区域按合成位置检测；不复制完整项目碰撞系统。无合法目标时按0.05秒步长复查，成功后重新经过完整吟唱；这也不同于真实core的120Hz固定步。单独的180HP起手判据只回答静止无暴击基准。

组合覆盖无道具、60%CDR压力、6件通用施法触发、GU11＋GT01回盾蓄能、火区职业、引爆职业与最多9件通用＋职业。库存为受控输入，不模拟九箱自然取得、品质或触媒抽奖。组合资格不满足的预设会跳过。

实际建模的通用范围：U03、GU05／06／07、P04／P05、GU11／GT01；GU15／17／18只提供基础状态接口和边界支持，没有把24通用全部放进场景。没有生命生存、受击AI、治疗、经济或Boss模型。

16火职业中14件有数值探针；B05减速与B09移速只保留设计作用说明，**没有把控制／移动效用换成DPS**。因此本工具不能证明这两件与纯输出宝物等价，也不能证明全部16件已经完成平衡。

## 事件和防递归

连续事件按同刻顺序执行：旧燃烧tick → 旧区域／到时G03 → 有效命中 → 新施法 → 到期清理。F07本体内先直伤和现有GT01首次命中，再存活检查和引爆，最后存活检查和G04安排。燃烧刷新保留下跳时刻，未来跳数按计划时点数计算，最多8／12。

F11有效主击已造成伤害时，即便直伤或GT01击杀主目标，仍从命中位置进行一轮邻敌扩散；不对尸体点燃。已有燃烧不占传播名额，传播没有即时直伤或二次扩散。遮挡仅在边界夹具中显式给出阻断对；常规场景无墙。

P04／G01只由自然施法计数，追加不递归。追加倍率仅缩放本体直击／区域，燃烧统一共享；追加F07不能复制已经消费的库存。P02／G03可暴击，但不点燃、不触发命中链，且沿当前行为不带F06释放攻击快照；新燃烧／引爆动态读当前站阵增益。GT01只据实际回盾蓄能，固定附伤不再次吃攻击或暴击。

G03比较旧自然到期与候选持续满2秒；旧区域在同刻到时优先于新法阵替换，提前消失无爆。G04只强化自然F07，成功消费且仍活才安排0.5秒后复燃；同敌2秒限制，死亡或战斗结束取消。模型有限窗口结束不补算延迟伤害。

## 可执行判据

| 判据 | 边界 |
|---|---|
| 三起手L1无道具／共鸣，静止180HP、首击命中时≤6秒解决 | 只验证明确受控基准，不作关卡难度／生存结论 |
| F03首落100＋完整8跳25＝300 | 对180HP假定首落命中、其余全空，0.4＋0.3＋4×0.5＝2.7秒 |
| 反复点燃稳定伤害率50／秒，P06不提高每跳／频率 | 攻击100且无增幅；P06增加覆盖时间和可兑现库存 |
| F11疏散6目标总输出／同参F01单体为0.8～1.2 | 特定身份设计初版目标，不扩成全部情境DPS相等 |
| F06三级总CDR60%、无P04时新G03有触发、旧为0 | 真实旧core与候选抽象结果分别报告 |
| 共享状态／消费／防递归／延迟取消／合法上限 | 手算、已知情况、固定seed刷新边界、事件终止检查 |

尚未给“整体输出是否合适”设一条伪造的通过线。用户允许强构筑跃升；需要未来实装后的相同敌群试玩决定机会成本、覆盖容错和受压表现。

## 复现

在D:/demo运行，均自动退出，不启动完整路线或互动交付：

```powershell
& 'D:/demo/Godot_v4.7.2-stable_win64_console.exe' --headless --path D:/demo --check-only --script res://tools/balance/formal_fire/runtime_baseline.gd
& 'D:/demo/Godot_v4.7.2-stable_win64_console.exe' --headless --path D:/demo --script res://tools/balance/formal_fire/runtime_baseline.gd
python tools/balance/formal_fire/baseline.py
python tools/balance/formal_fire/run.py
python tools/balance/formal_fire/report.py
```

`run.py --parameters <JSON路径> --out <目录>`支持保存其他候选；`--max-seeds 1`仅用于另存烟测，不能替代默认8-seed结果。原生当前基线先单独复现，候选运行检查其证据。工具和运行源哈希绑定在`run_manifest.json`；报告只读后处理另记自身来源，避免补充说明破坏原模型证据。

`identity_sensitivity.json/.md`保存修正模型后96组／768轨迹的选择依据；其参数哈希对应`initial-candidate/parameters.json`原字节，允许与后来选定的主参数不同。初版10%／G04＋1在修正模型下的12组／96轨迹也保留于该目录。更早修正前984矩阵与9组小表归`initial-candidate/retired-pre-correction`并标失效，不作为新参数证据。`identity_sweep.py`用于重现本次选择，应读取初版参数快照；常规调参另存结果，避免覆盖该历史。

结果：`runtime_baseline.json`、`baseline_summary.json/.csv`、`model_validation.json`、`rain_math.json`、`cashout_math.json`、`scenario_results.json`、`scenario_summary.csv`、`acceptance_checks.json`、`run_manifest.json`、`report.md`。无战斗胜率、真人成型率、Boss或最终30分钟结论；不改data、scripts、tests、存档，不导出或上传。

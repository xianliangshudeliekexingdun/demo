# 正式触媒／法术布局抽样模型

本工具只比较**设计中的抽取倾向与成长结构**，没有实现新学派、触媒、法术、价格或战斗规则。运行源 `data`、`scripts`、`tests` 均未修改。模型不计算攻击、召唤间隔、伤害、胜率、魔尘价格／回本或最终60房约30分钟。

## 来源与模型边界

- 先读取当前 `first_room_run.gd`、`courtyard_route_run.gd`、`meta_progression.gd` 及实际基础／局外／路线JSON。
- 现行资格是：未满八槽时允许新ID；已持ID未到三级仍可升级；先过滤，再逐张抽取，同屏不放回；旧MC01只倾向三个相关ID，倍率来自当前源1.5／1.75／2。图鉴或候选源旧status不覆盖实际调用。
- `runtime_fidelity.gd` 仅实例化当前First RefCounted，核对当前十火的四个持有状态与四个触媒等级。它不启动场景／战斗／互动游戏，不调用局外存档读取或写入，只写专属QA结果。Python不尝试重现Godot PCG的逐步随机流，只对照相同资格、权重和分布。
- 未来模型为2／3／6个已上线学派，各10个**合成法术ID**；未上线学派不进入池。所有已上线法术不受触媒ownership锁定；解锁触媒与取得该系法术是两件事。所有比较固定同一主系一级起手，**没有模拟无触媒时真实随机起手**。
- “六系10主＋50副全部合法”是概率数学锚点，**不等于实际开局必有60个合法候选**。轨迹只模拟等级／槽位资格；总纲新增的坍岩令已有构造前置、群灵号令／契约法阵已有召唤前置，以及其他标签、真实效用、职业宝物资格均未建模。`parameters.json`中的utility/tag/synergy eligibility omissions包含这一边界。参数文件与已接受结果哈希保持原样。
- 副系表示“任何非主系学派”。`mixed_four_four`目标为4个主系ID＋4个任意跨系ID；六系时后四个可来自五种学派，**不是指定两系4＋4的成型率**。

## 抽取顺序

每张卡都重新执行：合法池分主／其他 → 计算本张主池概率 → 均匀抽该池一个ID → 从本屏池移除该ID。池空则回退到另一池；总合法不足三时展示全部合法ID；全满返回空。没有固定主系槽位、保底、重抽、强制纯系或跨系封锁。

推荐方向：`q = 主合法ID数 / 总合法ID数`，`P主 = q + (1-q) × 倾向强度`，等级强度28%／40%／52%。两池非空时，主池首抽概率始终高于不装备基线，等级单调增加；只有本系、只有副系或总合法ID不超过展示数时，无法创造不存在的选择差异。

六系10＋50锚点的**首张**分别40%／50%／60%；抽走一张后q会改变，所以三张分布必须用条件概率计算。旧方案固定每张40%／50%／60%会在两系或满槽主6副2等状态反向降低主系机会，因此保留作否定对照。

## 选择策略与期限

`parameters.json`定义四种可重复的选择规则，均需接受一张当前合法卡，不能跳过或重抽：

- 主系偏好：有主选主，同优先级均匀选。
- 新学优先：先新ID，再主系。
- 升级优先：先持有ID，再主系，再高当前等级。
- 混搭偏好：尝试4主＋4任意跨系，先补缺额；缺额候选不出现时先升级，必要时仍须接受其他合法卡。

这四种规则不是实测真人行为，也没有把法术价值当作相同战力；只用于隔离“偏好如何改变取得结构”。每条轨迹沿当前45房36个书节点进行：固定一级起手，再最多23次成长到八槽三级，之后13处无合法法术可领。第23个书节点是28房；增加法术库不会自动增加槽位或成长次数。

## 复现

~~~powershell
& ./Godot_v4.7.2-stable_win64_console.exe --headless --path D:/demo --script res://tools/balance/formal_spell_framework/runtime_fidelity.gd
python tools/balance/formal_spell_framework/run.py
python tools/balance/formal_spell_framework/report.py
~~~

默认4个固定seed批次；168组扫描各1000条轨迹，推荐36组各5000条，共348000条。精确DP另有154个池状态／规则组合；Python六个条件案例各50000次抽取对照；当前Godot抽样桥另行记录，不冒充未来规则已经接入。

结果唯一写入 `build/qa/formal-spell-framework-20261018/`：`run_manifest.json`绑定原输入和来源哈希；`model_validation.json`为82项独立核对；`runtime_fidelity.json`为49项实际core桥；`exact_offer_cases.json`为精确概率；`sweep.json`／`recommended.json`为轨迹分布；CSV供设计文档引用。`report.md`区分数学结论、玩家效用假设和需要后续试玩的感知问题。

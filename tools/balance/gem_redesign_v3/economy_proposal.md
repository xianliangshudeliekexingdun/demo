# 新版宝石：获取、属性与养成提案

版本：gem-redesign-v3-economy-proposal-r3-20261022。**只供方案评审，未写入运行data、未制作游戏功能、未读写账号或执行迁移。** 参数文件为同目录`economy_parameters.json`，可复算工具为`economy_model.py`。以下为建议值，尚未获用户对数值与迁移的制作批准。

## 1. 架构与获得

- 装备为1枚固定机制核心＋3枚属性宝石。核心不携带随机普通词条、无等级，只能激活1种；属性宝石不能放入核心槽。
- 账号首次自选任意1种核心免费解锁，另自选3枚绿色I档主属性宝石；可选相同主属性，默认推荐攻击／冷却／护盾。模型以这三个不同主属性计算，不以礼包默认选择约束玩家。
- r3增加一次性新账号里程补给：账号累计真实结算清房达到15／30时各给12精粹，合计24。可由多次短局累计，预览、未结算房和同一结算重复请求不计；每个里程账号只领一次。24恰能将三赠绿升蓝，也可由玩家自由用于其他属性养成，不强制代花。无新货币、不抬高105尘路线收入，不改触媒费用。
- 其余9种核心各30魔尘定向解锁；永久解锁、局外免费换装，不设复制品、抽中率、核心改良或重复升星。
- 属性宝石单抽5魔尘，十连50，单抽／十连执行完全相同的序列，不额外赠抽。金币与魔尘／精粹不兑换。
- 局外装备与核心在出发时锁定，本局内不可换装、制作或采用改良候选。无新战斗按钮。

核心首次自选已提供完整机制，玩家不必先抽到金才尝试流派。代价是减少“核心与好词条同时随机命中”的收集高潮，后期随机追求转移到属性配置。金色是核心类别标识，紫色是属性宝石最高品质，两个目录分开显示，不形成“紫石等待升金”的误导。

## 2. 属性与数值

主属性决定该枚宝石的类型，副属性不重复主属性或同颗另一副属性；跨颗同类相加。主属性类型可通过制作定向选择，已有宝石不直接随机更换主类型，想换主类型则制作新宝石并预览旧石用途。

绿色=1条主属性，蓝色=1主＋1副，紫色=1主＋2副。品质只决定条数，主／副各自共享I／II／III档；同档数值不随品质变化。

| 属性 | 主I／II／III | 副I／II／III |
|---|---|---|
| 攻击 | ＋4／6／8 | ＋2／3／4 |
| 生命上限 | ＋20／30／40 | ＋10／15／20 |
| 护盾上限 | ＋8／12／16 | ＋4／6／8 |
| 防御 | ＋4／6／8 | ＋2／3／4 |
| 暴击率 | ＋3／4／6个百分点 | ＋1.5／2／3个百分点 |
| 暴击伤害倍率 | ＋0.10／0.16／0.24 | ＋0.05／0.08／0.12 |
| 冷却缩减 | ＋2／3／4个百分点 | ＋1／1.5／2个百分点 |
| 战斗移速 | ＋2%／3%／4% | ＋1%／1.5%／2% |

主属性每档为旧运行同属性档值的2倍，副属性保留旧运行档值。旧满配4颗×3行=12份旧词条；新3颗×（主2份＋副1份＋副1份）也为12份。**这是预算锚点，不是各组合等强证明。** 新方案允许主属性集中，减少了其他属性占比，旧12行直接删成新9行不构成合格迁移。

实际攻击100、生命300、盾100、基础暴击5%／暴伤1.5的属性模型中，6组直接施法优化网格（前置CDR0／30%／60%，吟唱／CD为.25／1.5与.5／6）新最大输出相对旧最大输出约＋2.33%—3.34%。防护三属性的10组新配法，相对旧四颗生命／护盾／防御全III的有效生命，约－4.20%—＋2.59%。这些不是全六系、宝物、核心与完整战斗的实测。

叠3个同类III主属性分别可得攻击＋24、生命＋120、盾＋48、防御＋24、暴击＋18个百分点、暴伤＋0.72、CDR＋12个百分点、移速＋12%；这些是不同的装备方案，不能同时取得。现有60%总CDR、35%战斗移速加成与45%综合减伤边界继续有效。例如已有50%CDR再加12个百分点只到60%；已有30%移速加成再加12%只到35%（基础5米／秒为6.75米／秒）；已有防御70再加24的原始减伤48.45%，最终仍封45%。

## 3. 抽取与品质保障

| 品质 | 每次基础概率 | 主／副类型与档位 |
|---|---|---|
| 绿 | 60% | 主类型8类等权，主档I／II／III=60%／30%／10% |
| 蓝 | 30% | 同上，副从排除主属性的7类中等权；档位同分布 |
| 紫 | 10% | 同上，两副类型不放回；各行档位独立同分布 |

连续9抽未出紫，第10抽必紫；提前出紫立即重置计数。无核心进入该随机池，无指定主属性保底。计数和RNG跨关闭、重启保存，制作、升品和重铸不推进抽取保底。

保底后的长期紫色综合概率为15.3534%，平均每6.5132抽一紫；基础概率仍是10%。这是精确更新周期计算，不能把6.51解释成每人六七抽必出。定向主属性可通过精粹制作，所以不以随机主属性作为不可绕过的构筑门槛。

## 4. 制作、升品、重铸与提档

| 操作 | 精粹成本 | 结果与保护 |
|---|---|---|
| 制作绿／蓝／紫 | 3／10／30 | 指定主属性；全部初始I档；所需副类型随机且不重复 |
| 分解绿／蓝／紫 | 得1／3／10 | 仅按品质给基础精粹；不返魔尘或追加返还提档投入 |
| 绿升蓝／蓝升紫 | 8／20 | 100%成功，保留已有行及档位；新增副属性随机类型、固定I档 |
| 主属性I→II／II→III | 8／16 | 类型不变，100%成功，只提高选择行 |
| 副属性I→II／II→III | 6／12 | 类型不变，100%成功，只提高选择行 |
| 随机重铸一条副属性类型 | 5 | 保持原档；排除主／另一副／当前类型；旧新二选一，保留旧也付费 |
| 定向重塑一条副属性类型 | 25 | 指定合法类型，保持原档，确定成功；选择前展示数值 |

蓝石随机重铸有6种候选，紫石有5种；紫石仅追1个指定类型时，随机平均5次=25精粹，90%在11次内命中=55精粹。定向25提供明确终点；若多个类型都可接受，随机仍有更低期望成本。定向不改变档位，因此先提档再换类型不会丢失已付提档价值。

三枚已有I档绿石升到紫共需3×（8＋20）=84精粹；直接制作三紫需90。若这套三紫全部I档且两副都需改成指定类型，再完成全部III，保守确定上界为：84升品＋150定向类型＋72主提档＋108副提档=414精粹。直接新制则420。实际随机抽中、已有合适类型或高档会降低成本；这不是要求玩家毕业的最低门槛。

非套利：制作3／10／30均高于分解1／3／10；升级8／20均高于对应分解差额2／7。绿制作后逐级升紫合计31，略高于直制30；蓝制作后升紫合计30，与直制相同。重铸、提档不提高分解产出，无法靠循环制作／升品／分解净赚精粹。

锁定阻止分解与改良，已装备但未锁可改良；选择候选前，费用、RNG与唯一候选ID同事务保存，关闭／重启不会免费换候选或重复扣费。满级、重复类型或非法操作不扣材料。核心解锁不参与分解、提档或候选抽样。

## 5. 预算与进度

沿用运行收入：已清0／15／30／45／60房分别0／15／45／75／105魔尘，商店不计房，不添加Boss奖金、免费挂机或金币兑换。首个额外核心需30尘，专门攒钱时最早清到23房可支付（31尘）；两次各15房结算也能购买。剩余9核心总价270尘，只攒核心相当于3次完整路线收入；同时升满首触媒原20＋40则总价330，需要4次完整路线收入，尚有90尘可抽18次。

模型对三种消费政策、每次仅清15／30／45／60房分别模拟，三固定种子每政策每深度合计1200账号、20次路线，合计14400条账号轨迹。60房“平衡政策”先攒第2核心，之后每次收入约30%留作核心预算，每次最多按政策购买1核，首触媒II／III仍付20／40，剩余抽石并保留更适合目标主属性的宝石、分解闲置、先升品再定向类型和提档。这是模拟玩家消费策略，不是游戏限购或新增钱包。

最终r3平衡政策：

| 里程碑 | 中位数／90分位完整路线次数 | 初设目标与状态 |
|---|---|---|
| 第2核心 | 1／1 | 30尘确定获得 |
| 三槽至少蓝 | 1／1 | p90≤2达到，首轮24里程补给足以覆盖三次升蓝 |
| 三槽紫 | 3／3 | p90≤4达到；样本最慢3次 |
| 三紫指定两副＋九行全III | 8／9 | p90≤12达到；样本最慢10次 |
| 全十核心 | 9／9 | 受每次约买一核的消费政策影响，非系统最早上限 |

优先收集核心可在3次完整路线收入拿齐；优先属性政策的指定完美套中位／p90为6／7次完整路线，推迟全核心。上述次数是假设反复达到同一清房深度的资源账本，不是通关概率、真人时长或自然路线证据。

无里程补给的r2基线保存在`build/qa/gem-redesign-v3-20261022/economy-r2-no-milestones/`，同时保留当时参数、模型与报告。反复只清15房时，r2平衡政策三蓝中位／p90=12／13次，初期资源竞争过重。因此r3新增的24精粹是针对早期可用装备的有限补给，未再调低养成费或增加反复收益。

|---|---|---|---|
| 15 | 2／2 | 17／19 | 20次内未达到 |

0／12／24一次性补给的15房敏感性分别显示：只给12仍不足以覆盖三槽升蓝，三蓝约10／12次；24把三蓝降到2／2。补给优先保障起步，长期停15房时三紫、完美套仍慢，不能把满通105尘替代新手收入或保证所有进度问题已解决。这里同时购买新核心和优先升首触媒会挤压属性投入；可通过玩家延后触媒／收集支出改善，但本轮未用假想技能进步掩盖这一边界。

无补给模型1.2下，25／35（蓝升紫／直制紫）候选在300账号同情境中三紫p50／p90=3／4、完美套9／10；20／30为3／3、9／9，15／25为3／3、8／9。选择20／30提供温和进度改善并保留后续投入。r3加补给后，300账号三个价格候选的三紫p90均为3、完美套p90均为9，因补给而进一步加快；保持20／30，不为追求更快而继续调费。25／35并非违反r2三紫p90≤4，只是更慢，不能沿用旧模型的错误失败判断。核心价20／30／40与紫保底8／10／12另有敏感性表。

成熟期将所有抽到的宝石分解，精粹期望约2.946／抽；105尘21抽约61.87精粹。新玩家会保留可用石，不能把这一成熟期全分解值当首局净收入。实际模型按保留／替换与材料操作逐笔记账，不允许负余额。

## 6. 旧资产继承建议

以下是待评审迁移建议，不是实施授权：

- 旧inferno／coffin／fracture／echo／sacrifice／aegis可解锁对应新方向，保留英文ID兼容；发生机制变化要在更新说明中直接告知，不把同名视为效果完全未改。
- 旧reactor／stride不强行映为无关玩法；每种首次持有建议换1次新核心自选权益。两种权益和新手首免是否抵扣，需由最终迁移表明确，不能发放后再追回。
- 旧金原3条普通属性按原值、原档保留为“过渡属性石”，与已有MG01—03传承体系区分；不自动改主属性、删行、降档或强制分解。允许继续装备属性槽，再提供可预览的新式转换。
- 重复旧金的重复核心部分可建议返20精粹，同时保留原3行的过渡石（若其基本分解名义10），合计名义30与旧金分解30相符。**名义分解值对齐不能证明实际装备效用或迁移瞬时强度完全守恒。** 锁定仍锁定，返精粹不自动分解属性资产。
- 已扣费未选择的普通／核心改良，先保留原两分支与原费用，不重抽、不再次扣费。让玩家选定后，再按选定旧宝石展示继承预览；读档不自动兑现或选择。
- 旧普通石三档原数值继续保留；为新主属性翻倍的转换必须可选择、可预览，不能把不合新主副结构的旧石直接判损坏。装备关系、锁定与实例来源可追溯。
- 旧紫／金保障与出金进度需要独立折抵方案，不能因为新池无金就清零。旧紫或金未出计数可保留到新紫计数；金进度如何折成定向解锁权益，需明确进度口径与防重复凭证后再批准数值，不在本轮擅发补偿。

## 7. 核算范围与复算

运行：`python tools/balance/gem_redesign_v3/economy_model.py`。可选`--parameters`和`--output`，输出必须在本工程build/qa。最终结果位于`build/qa/gem-redesign-v3-20261022/economy/results.json`及`report.md`。

模型1.3最终44项校准／回归0失败，已核来源、已知105尘预算、品质概率总和、十抽强制紫／重置、制作与升品无套利、低收入留款策略、负余额／收支守恒、删失分位口径以及旧新属性预算。新补给另核零房不发、15＋15与30合并等价、已领不重发、无新增房不发、长期最多24。Python使用独立固定seed，不复刻Godot RNG。主矩阵14400账号轨迹，0／12／24敏感性每格同三seed×400=1200账号；没有把这些模拟轨迹当真人局数。

模型修正保留为回归：早稿贪心把15尘全抽会永远无法攒30买核心，现按消费政策留款；删失分位使用完整账号群体而非仅统计达到者；禁止用低品质新石撤销已达到的品质里程碑。最终复核还修正首个额外核心留款错误：只保留所需30，不把整笔105的剩余75也锁为核心预算；同时修正优先属性政策首局只买1个额外核。模型1.1下的三蓝p90=3及旧价格扫被这项实现缺陷污染，不再作为参数判断；1.2已重新执行全部价扫和1200账号轨迹并冻结为无补给基线；1.3在同样正确模型上加入有限补给，再运行同规模对照。参数选择以最终1.3与冻结基线分别标明的范围为准。

未覆盖完整战斗、核心机制叠乘、真人选择／死亡分布、自然通关时长、像素／性能、实际账号迁移。尤其固定主属性改变随机可用性，后续需检查攻击主属性是否过于通用、护盾／防御主属性在新血晶及岩系中的边际收益，以及冷却已封顶时换装信息是否清晰。
